# Override scheduling follow-up — 2026-09-25

This follows the [Relay type-checking benchmark](2026-09-25-relay-types.md). The baseline is `5fe410b9`.
Only tests and documentation changed; runtime source, fixtures, worker limits and timeouts are unchanged.

## Change and preserved coverage

The single override file became New Tab, Bookmarks, History and competing-entrypoint files. A shared helper
registers the page support checks. Every scenario still creates and disposes its own fixture and launches its own CLI build.
There is no shared build cache, shared mutable application or `test.concurrent`.

All **33 unique full test names** match the baseline, and AST comparison found the same **17 assertion statements**.
The matrix remains three pages × five browsers × two manifest versions, plus three competing-entrypoint cases.
The isolated override run passed four files / 33 cases in 6.33 seconds of Jest-reported time.

## Measurements

Apple M3 Max, 16 logical CPUs, macOS arm64, Node 24.5.0. The existing macOS `--no-sparkplug` workaround remains enabled.
Commands ran sequentially outside the sandbox. Package build time is excluded from group measurements; the package was built
once before the series and production code was not edited afterward. Whole-command time uses Python `time.perf_counter()`.
All group commands include Jest JSON reporting and an explicit worker count.

At eight workers each state has one warm-up followed by three measured runs. At two workers the first before/after pair
followed those series; two additional alternating before/after pairs checked the initial difference. For these repeats,
a script temporarily restored only the original override test or the four new test files, verifying their contents and
restoring the final split in `finally`. Other sources and dependencies stayed unchanged.

| Workers | Before: median (range) | After: median (range) |
| ------- | ---------------------- | --------------------- |
| 8       | 22.51 s (22.25–22.71)  | 16.52 s (16.21–17.61) |
| 2       | 52.40 s (51.32–53.63)  | 53.16 s (52.02–54.29) |

At eight workers the group is **1.36× faster**.
At two workers the ranges overlap; no reliable speedup is established. The build count remains 33, so splitting removes
the serial tail when workers are available but does not reduce the compilation work. Two workers match the current CI
setting; these local macOS runs are not measurements of the Linux/Windows CI matrix or its coverage-enabled job.

Build + types passes **40 suites / 285 tests**, versus 37 suites / 285 tests before the split.
The next longest file in the eight-worker runs is the isolation watch integration, around ten seconds; the group also
includes other jobs and scheduling overhead, so its total does not equal that file's duration.

## Final validation

- `typecheck`, test inventory and formatting passed; inventory has 206 files, each in exactly one project, and zero local module mocks.
- `npm run check`: 175 suites / 1961 tests plus framework and 24 fixture typechecks, 31.93 seconds for the whole command.
- Full `npm test`: 206 suites / 2003 tests, including Chrome and Firefox, 58.47 seconds for the whole command.

The full/check timings are single observations, not new before/after series. The preceding Relay report recorded
52.32 seconds for the full command, versus 58.47 seconds here, so these results do **not** establish a full-suite speedup.
The unchanged Chrome override browser file took 16.46 seconds here versus 10.59 seconds in that earlier full run;
this observation does not establish the cause of the difference.

## Reproduce

[Raw results](2026-09-25-override.json) include all runs, per-file durations, scenario names, worker counts and exit codes.
At each revision, build once, warm up the selected group, then measure it three times. Use unique JSON output filenames.

```sh
npm run build
npm run test:run -- --selectProjects build types --maxWorkers=8 --json --outputFile=/tmp/override-8.json
npm run test:run -- --selectProjects build types --maxWorkers=2 --json --outputFile=/tmp/override-2.json
npm run test:run -- --selectProjects build --testPathPatterns=tests/integration/build/override
npm run check
npm test
```
